Wallet access in the original AirGap Vault

Scope
This implementation is in airgap-vault. The separate web and web-local projects
are not part of this change. Native Keychain/Keystore encryption, Paranoia and
their authentication policies remain unchanged. There is no idle timer.

User flow
1. Create/import a mnemonic and save a named Secret with a confirmed nonempty
   default password D.
2. The Secret list displays the base Secret without deriving or displaying its
   password-specific accounts.
3. Open a Secret and enter its wallet password. D selects an empty BIP39
   passphrase. A registered Pi selects the exact entered Pi. Unknown input fails.
4. Add the desired coin accounts, networks and paths within the selected wallet.
   A newly registered Pi initially has no accounts; add accounts after opening it.
5. Open Secret management from the default wallet to register/remove Pi or change
   D. Changing D preserves addresses. Changing Pi is not a password reset: it
   selects a different derived wallet.
6. Return to the Secret list, switch Secrets, or background the native App to close
   the current wallet. Native authentication-only interruptions do not close it.
7. Open the desired wallet and add its accounts before scanning a signing request.
   Requests cannot silently select another Secret or password branch.

Storage and algorithms
Public app storage contains Secret metadata and walletAccessVersion=1, with an
empty wallets array. It contains no password verifier, mnemonic, account public
key or password-specific account configuration for new-format Secrets.

One native encrypted item, keyed by secret.id, contains:
  {format: "airgap-wallet-access-v1", secretId, entropy, registry}
The registry contains salted password verifiers and each registered password's
account templates: protocol, network, derivation path, HD type, status and index.
The native item remains protected by AirGap's existing platform encryption.

Password verification uses the existing vendored PBKDF2/HMAC-SHA512 primitive,
2048 iterations, independent random 16-byte salts, and 32-byte outputs. This is
an application verifier, not an extra encryption layer for the mnemonic and not
a change to BIP39 or protocol-specific key derivation. No Argon2 is introduced.
Passwords use raw UTF-8; whitespace, case and Unicode representation are kept.
Each protocol still applies its own existing derivation semantics. Different raw
strings can yield the same wallet for protocols that normalize those strings.
The verifier accepts at most 1024 UTF-8 bytes. A Secret has at most 32 registered
credentials, including D. There is no configurable memory parameter.

Runtime access
Only the current wallet's accounts and its Pi are retained while open. Pi is not
placed in route state, NgRx actions or public metadata. D itself is not retained
as the derivation passphrase. The authorization epoch changes on closing or
switching wallets, without adding an idle timeout. Signing, sharing and sensitive
page results are rejected if their epoch has expired. Native storage reads still
use the original platform authentication.

Recovery and compatibility
Android's existing RecoveryKey copies one native item. Using one encrypted record
therefore restores the mnemonic, verifier table and account templates together.
It is a POINT-IN-TIME SNAPSHOT. Changing credentials or account templates marks
the existing recovery snapshot as outdated in app metadata. Generate and save a
new RecoveryKey after such changes. Old snapshots can restore old passwords and
accounts. The original native recovery trigger limitations remain unchanged;
this work does not claim to repair every Keystore failure mode.

Mnemonic/social recovery/BIP85 outputs do not include the application verifier
registry. Preserve the mnemonic, actual Pi values and account configuration for
independent wallet restoration. A password hash cannot recover a forgotten Pi.
Removing a Pi registration removes local access/configuration, not chain assets.

This new project does not automatically migrate old-format Secrets. Existing
records are preserved without deriving or exposing them through the new flow.
An existing mnemonic cannot be silently re-imported over the old record. Back up
legacy data using the original application before moving to a fresh installation.

Validation
Run the new behavior and boundary tests from airgap-vault:
  node --test tests/*.test.cjs
They execute application TypeScript and real ETH/BTC/DOT crypto libraries with
mocked native storage and Angular/UI boundaries. They do not replace device tests.
Type/template checking:
  node node_modules/@angular/compiler-cli/bundles/src/bin/ngc.js --project src/tsconfig.app.json --noEmit
Production web assets for the native shell:
  node --max-old-space-size=8192 node_modules/@angular/cli/bin/ng build --configuration production

Native biometric dialogs, genuine background events, Keychain/Keystore recovery,
and external BTC PSBT/MetaMask integrations still require device validation.
